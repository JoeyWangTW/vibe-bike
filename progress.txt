## Codebase Patterns
- Arduino sketches go in `firmware/<name>/<name>.ino` — Arduino CLI requires directory name to match sketch name
- Use `noInterrupts()`/`interrupts()` when reading ISR-shared volatile variables from loop()
- ESP32 IO35 is input-only — no internal pull-up available, must use external 10K to 3.3V
- Compile check: `arduino-cli compile -b esp32:esp32:esp32 firmware/<name>` — fast, no board needed
- FQBN is `esp32:esp32:esp32` (not esp32dev or other variants)
- Speed/distance are derived values — extend existing sketch rather than creating a new one
- Use `#define` for bike-specific calibration constants (DISTANCE_PER_REV_M) so they're easy to tune
- Distance accumulation uses pulse count delta, not RPM × time — more accurate, no drift from timing
- TFT_eSPI User_Setup.h is at `~/Documents/Arduino/libraries/TFT_eSPI/User_Setup.h` — must match the target board
- ESP32-32E display pins: CS=15, DC=2, SCLK=14, MOSI=13, MISO=12, BL=21, RST=EN (shared)
- Use ILI9341_2_DRIVER + HSPI port for this board (not ILI9341_DRIVER, not FSPI/VSPI)
- Backlight on IO21: HIGH = on — must set manually with digitalWrite in setup()
- Dirty-region display updates: track prev values, only redraw on change — prevents flicker, saves SPI bandwidth
- Font 7 = 7-segment (huge, for main number), Font 6 = medium digits, Font 4 = medium text, Font 2 = small labels
- `bike_dashboard` is the main production sketch — it combines pulse counter + display + all future features
- Session state machine: READY → ACTIVE → PAUSED → ENDED — use enum + switch/case for clarity
- Active time accumulation: `accumulatedActiveMs + (now - activeStartTime)` — handles pause/resume intervals
- RPM timeout (3s) is independent from session pause (30s) and end (2min) timeouts
- SD card uses VSPI (CS=IO5), display uses HSPI — no bus conflict, both work simultaneously
- Open/close SD file per write — safer than keeping open (power-loss resilient)
- Use `double` for accumulators (sumRpm) to avoid float precision loss over many samples

## 2026-02-24 - VB-004: Implement pulse counter firmware
- Created `firmware/pulse_counter/pulse_counter.ino` — production pulse counter
- Hardware interrupt on IO35 (FALLING edge) for reed switch detection
- 50ms debounce in ISR to reject reed switch bounce
- RPM calculated from pulse interval: `60000.0 / interval_ms`
- Edge case handling:
  - Stopped: 3-second timeout with no pulses → RPM = 0, smoothing buffer cleared
  - Very slow: RPM below 10 treated as stopped (noise rejection)
  - Very fast: RPM above 200 rejected as bounce artifact (not added to buffer)
- 4-sample rolling average for RPM smoothing
- Serial output at 500ms intervals (2Hz) — shows smoothed RPM, raw RPM, pulse count, interval
- Atomic reads of ISR variables using noInterrupts()/interrupts()
- Compiles cleanly: 286KB flash (21%), 22KB RAM (6%)
- Files changed: firmware/pulse_counter/pulse_counter.ino (new)
- **Learnings for future iterations:**
  - The test_reed_switch sketch already had basic interrupt + debounce — build on it, don't rewrite from scratch
  - IO35 is input-only on ESP32, so `pinMode(pin, INPUT)` is correct (no INPUT_PULLUP available)
  - Rolling average smoothing prevents jittery RPM display without adding latency
  - Keep ISR minimal — only set flags and timestamps, do math in loop()

## 2026-02-24 - VB-005: Calculate speed and distance
- Extended `firmware/pulse_counter/pulse_counter.ino` with speed and distance calculations
- Speed: RPM × DISTANCE_PER_REV_M × 60 / 1000 → km/h (or mph if USE_METRIC=false)
- Distance: accumulated per pulse using pulse count delta × DISTANCE_PER_REV_M (meters)
- Configurable constants:
  - `DISTANCE_PER_REV_M` = 6.3m (default: 3:1 flywheel ratio × 2.1m wheel circumference)
  - `USE_METRIC` = true/false for km/h+km vs mph+miles
  - `KM_TO_MILES` = 0.621371
- Distance uses pulse-count-based accumulation (not RPM × time) for accuracy
- Only counts distance when RPM ≥ MIN_RPM (noise rejection)
- Serial output updated: RPM, speed with units, distance with units, pulse count
- Compiles cleanly: 287KB flash (21%), 22KB RAM (6%)
- Files changed: firmware/pulse_counter/pulse_counter.ino (modified), prd.json (updated)
- **Learnings for future iterations:**
  - Accumulate distance from pulse count delta rather than RPM × elapsed time — avoids floating-point drift
  - Indoor bike distance conversion is a guess — 6.3m/rev is reasonable for ~3:1 gear ratio
  - Keep unit conversion in helper functions (rpmToSpeed, getDisplayDistance) so the main loop stays clean
  - `const char*` return type works fine for unit labels in Arduino/ESP32 — no need for String

## 2026-02-24 - VB-008: Auto-detect session start and stop
- Added session state machine to `bike_dashboard.ino` with enum SessionState
  - READY → ACTIVE (first pulse) → PAUSED (30s timeout) → ENDED (2min timeout)
  - PAUSED → ACTIVE on resume (pulse detected during pause)
  - ENDED is terminal — stays ended
- Active time tracking redesigned:
  - `accumulatedActiveMs`: sum of completed active intervals
  - `activeStartTime`: when current active interval started
  - `getActiveTimeMs()`: returns accumulated + current interval
  - On ACTIVE → PAUSED transition: freeze time using `lastPulseTimeLoop - activeStartTime`
  - On PAUSED → ACTIVE resume: start new interval with `activeStartTime = now`
- RPM timeout (3s) and session pause timeout (30s) are independent — RPM zeroes faster than session pauses
- Color-coded status: green PEDALING, yellow PAUSED, red ENDED, grey READY
- `lastPulseTimeLoop` copies ISR's lastPulseTime for safe use in state machine calculations
- Compiles cleanly: 335KB flash (25%), 23KB RAM (7%)
- Files changed: firmware/bike_dashboard/bike_dashboard.ino (modified), prd.json, docs/status.md, docs/worklog.md
- **Learnings for future iterations:**
  - Use enum for state machines — cleaner than booleans, switch/case makes transitions explicit
  - Active time needs interval accumulation, not simple `now - startTime` — can't handle pauses with a single timestamp
  - Keep RPM timeout separate from session timeouts — different thresholds for different purposes
  - State machine function should be separate from loop() for clarity and testability
  - `lastPulseTime` from ISR is used both for RPM timeout and session state — copy once per loop iteration

- Graceful degradation: `sdReady` flag — dashboard fully functional without SD card
  - "SD" (green) or "--" (red) indicator in top-right corner of display
  - Warning printed to serial if SD not available
- Status bar shows "SAVED" instead of "ENDED" when session data is written
- Compiles cleanly: 381KB flash (29%), 23KB RAM (7%)
- Files changed: firmware/bike_dashboard/bike_dashboard.ino (modified), prd.json, docs/status.md, docs/worklog.md
- **Learnings for future iterations:**

  - Use `double` for sumRpm accumulator to avoid float precision loss over many samples
  - `sessionLogged` flag is essential — state machine can re-enter ENDED check on every loop iteration
